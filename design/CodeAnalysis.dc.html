Análise de Integração: React Codebase vs Design Components

Identificação de elementos reutilizáveis e padrões de implementação

1. Estrutura & Arquitetura da Aplicação React

✓ PADRÃO UTILIZADO

  • • State management com React.useState()
  • • useMemo() para cálculos de métricas
  • • Componentes funcionais (moderno)
  • • Props passagem de dados
  • • Callbacks para interações

⚠ DIFERENÇAS DO DESIGN COMPONENT

  • • React JSX vs HTML template literal
  • • Tailwind CSS vs inline styles
  • • Lucide icons vs emoji/SVG
  • • TypeScript opcional vs plain JS
  • • Build step necessário vs bundler-less

2. Dados Reais - INITIAL_PRODUCTS (Planilha de Consumo)

A aplicação React integra dados reais da planilha de consumo v.2.0 com 10 itens principais:

Exemplo de item:

{ code: "1 50 05 0024 8", name: "DESINFETANTE PARA USO PROFISSIONAL - 5L",

  priority: "Alta", frequency: "Semanal", stock: 52,

  avgConsumption: 10.308, category: "Higiene", verify: true }

✓ PRONTO PARA REUTILIZAR

Os dados podem ser copiados diretamente para o estado das Design Components (ComprasModule, Dashboard analytics, etc.)

4. Padrões de Componentes Reutilizáveis

Card Pattern

React: className="bg-white p-6 rounded-2xl border border-gray-200/80 shadow-sm hover:shadow-md"
DC: Usar inline styles equivalentes com border-radius 8px

Toggle Switch

Implementação: Button com width 44px, altura 24px, bg dinâmica, dot animation transform

Badge/Label

Usado extensamente: priority badges, status, role indicators — cores semânticas (Alta=rose, Baixa=gray)

Grid Responsivo

grid-cols-1 sm:grid-cols-2 lg:grid-cols-3+ — padrão Tailwind com gap-4 ou gap-6

5. Lógica de Negócio Implementada

✓ PRONTO PARA PORTAR

  • generateSamplingScale() — filtro e embaralhamento
  • handleCountChange() — cálculo divergência
  • formatPhone() — máscara telefone
  • handleTogglePermission() — RBAC toggle
  • useMemo stats — cálculos KPI

⚠ REQUER ADAPTAÇÃO

  • simulador de scanner → validator simples
  • triggerToast() → sistema de notificação DC
  • state management → DC renderVals()
  • onClick handlers → event listeners
  • Tailwind classes → inline styles

6. Design Tokens Utilizados

Tokens React (Tailwind) Valor DC Equivalente
bg-[#1C543A] #1C543A background-color: #1C543A ✓
rounded-2xl border-radius: 16px border-radius: 8px (spec)
shadow-sm / shadow-md 0 1-2px / 0 4-12px box-shadow: 0 2px 4px rgba(...)
gap-4 / gap-6 16px / 24px gap: 16px; no Tailwind
text-xs / text-sm 12px / 14px font-size: 12px/13px ✓

✓ Recomendações de Integração

  1. Copiar dados INITIAL_PRODUCTS: Já testados e validados — usar como state do ComprasModule e Dashboard
  2. Portar lógica de negócio: generateSamplingScale(), handleCountChange(), formatPhone() → convertê-los para funções de classe DCLogic
  3. Reutilizar padrão sidebar: Layout 2-coluna pode ser adaptado (mas DC preferem layout simples, então apenas referência)
  4. Cores semânticas: Amber, Rose, Sky, Emerald já estão alinhadas com spec — manter padrão
  5. Animações: React usa transition-all duration-300 — DC usa CSS @keyframes (ambos funcionam, DC preferem for streaming)
  6. Sistema de notificações: Toast já existe em ambos — padronizar mensagens e tempos de auto-dismiss (4-5s recomendado)
  7. Backend API: Código React é simulado — definir contratos de API (endpoints, payloads) para próxima fase

RBAC / Usuários ✓ ✓ Ambos têm — matriz RBAC 3 usuários
Perfil / Meus Dados ✓ ✓ Ambos implementados — dados sincronizados
RH / Compras Modules — ✓ DC tem estrutura — React não detalhou
